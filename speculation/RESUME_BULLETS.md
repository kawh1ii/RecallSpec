# 简历表述建议

**RecallSpec v2：跨请求草稿检索与验证反馈（2026.10–2026.11）**

- 基于 vLLM 0.32.0 V1 worker 增设显式扩展点，对齐请求 ID、真实提示词边界与已提交 token；实现 50,000 键 LRU/TTL 索引、整批先查后写和请求完成清理，不索引未确认草稿。
- 按实际已调度草稿核算接受量，处理截短、未调度与来源替换；实现长匹配优先及候选冷却，完成 31 项回归；3B batch-invariant 模式下，64/128-token 输出分别通过 81/81 完整 ID 对照，对照无推测及原生 n-gram。
- 在 RTX 4090、Qwen2.5-3B BF16、128-token、batch 1 的高重复续写中，缓存预热后三种子延迟中位数由 1.088s 降至 0.160s（6.78×），包含任务首轮的 12/12 请求完整输出一致；普通问答存在开销和数值差异，不外推一般收益。

计时比值使用每个种子后续三轮的中位数，再跨种子取中位数。包含首轮的四次调用总耗时口径约2.50×，不能把6.78×写成冷启动效果。batch8有慢批和输出差异，当前不建议在简历里突出6.02×。

门控没有测得稳定净性能收益，不能写成“自适应策略进一步提升xx%”。原生目标验证和模型计算属于vLLM，本项目没有自行实现CUDA算子。新版尚未推送公开GitHub，不应保留指向旧版源码的链接并把它当作新版证据。
